# Quad View: integration map

This page is for whoever merges or maintains Quad View. It lists every place
the feature touches, what each piece does, and the rules that keep it from
affecting other rendering methods. Player-facing settings are in
[quad-view.md](quad-view.md); the history of the engine-specific fixes is in
[quad-view-ue4-ue5.md](quad-view-ue4-ue5.md).

## The one rule

Quad View is Rendering Method 3 and is off by default. Every code path it adds
is behind one of two checks:

| Check | Meaning | Used by |
| --- | --- | --- |
| `VR::is_using_quad_view()` | The method is selected and no mode that excludes it is on (AFR, 2D screen, stereo emulation). | Settings, gaze sampling, the cvar overrides. |
| `FFakeStereoRenderingHook::is_quad_view_active()` | The engine is rendering four views this frame. Adds: not NASCAR, no SceneView/Splitscreen compatibility, UE4 opt-in and its settle gate. | Every hook, both composes, the submit. |

With any other rendering method both return false and no Quad View code runs,
with one exception: `get_desired_number_of_views_hook` answers 4 during
`PostInitProperties` when Quad View is *configured*, because Unreal sizes
`LocalPlayer::ViewStates` only once.

These are new files. They can be taken as they are.

| --- | --- |
| `src/mods/vr/QuadView.hpp` | Portable math and bookkeeping: slots, atlas layout, sharp window, gaze filter, UE4 call order, LOD offset finder, per-frame snapshot, projection, compose rects, sprite settings packing. No Windows, D3D or UESDK includes. |
| `src/mods/vr/QuadViewVR.cpp` | The `VR` member functions that exist only for Quad View: cvar overrides, culling driver, snapshot accessors, settings panel. |

`quadview::` and `QuadView` finds all of them.

## How a frame flows

1. **Pose update (game thread, `update_poses`).** The gaze is sampled at the
   predicted display time and filtered. The atlas layout and the two sharp
   windows are stored in that frame's `PipelineState` as one `FrameSnapshot`.
2. **View setup (game thread, stereo hooks).** Unreal asks for four views. Each
   hook resolves the view index, reads the snapshot of the frame being built
   (`get_quad_view_frame_game`) and returns the view's atlas rect, eye offset
   and projection.
3. **Render (Unreal).** Four views into one render target: wide pair on top,
   sharp pair below.
4. **Compose (render thread, `on_frame`).** The compose reads the snapshot of
   the frame being presented (`get_quad_view_frame_render`), stretches each wide
   view over its eye and draws the sharp view where its window lies.
5. **Submit (`end_frame`).** Ordinary stereo, one layer, no depth.

Steps 2 and 4 use the same snapshot for the same frame number. That is the
invariant that keeps the sharp image and its window together.

## Engine state Quad View changes, and restores

All through `QuadViewCVarOverride` in `QuadViewVR.cpp`, which saves the game's
value and puts it back when Quad View or the option is turned off.

| Console variable | When | Why |
| --- | --- | --- |
| `r.Tonemapper.Quality` → 1 | *Remove vignette* | Each sharp view would get its own vignette. |
| `r.DefaultFeature.AutoExposure`, `r.EyeAdaptationQuality` → 0 | *Share exposure* | The four views would adapt to different brightness. |
| `foliage.MinimumScreenSize` | *Cull objects smaller than* > 0 | Culls tiny foliage in the wide views. |
| `r.EmitterSpawnRateScale` | *CPU particles* < 1 | Thins Cascade particles. |
| `r.AllowOcclusionQueries`, `r.GPUStatsEnabled` → 0 | UE4 only | Query crash on the first four-view frame. |

## Building and testing

- `build-dll.bat` does an incremental Release build of `UEVRBackend.dll`.
- The shaders are compiled by `compile_shaders.bat` as a pre-build step. The
  D3D11 shader needs FXC from the Windows SDK.
- `quad-view-tests` covers everything in `QuadView.hpp`. The rendering paths
  need a headset; the log lines to look for are listed under *Verification* in
  [quad-view-ue4-ue5.md](quad-view-ue4-ue5.md).
