refresh, not packaged-game or HMD runtime verification. No installed test

## Important findings and changes

| Area | November change and treatment |
| --- | --- |
| Console variables | `FResolvedContext` adds `AnchorTag`. UE6 uses 32 zero-initialized bytes covering both name tags and the priority flags, instead of the old 16-byte buffer. No priority escalation, no UE5 call-storage change. |
| Scene families | Render requests, render context and HDR paper white precede `Scene`. Restrict discovery to reviewed prefixes, exact views/target validation and a unique scene candidate; do not treat the request array as a scene. Re-prove UE6 layouts instead of loading an older cache. |
| View extensions | `PostCaptureViewFamily` and render-thread renderer creation change the callback order. Accept October or November topology only after observing the corresponding active slot, advancing frame values and exact view-to-family backlinks. UE5.9's topology is not a UE6 fallback. UE6 cached callback mappings are not replayed. |
| Stereo interface | The world-aware `GetExternalViewState` overload adds a virtual entry. Existing stock-vtable instruction/reference discovery locates render-texture and RT-manager methods independently; no synthetic UE5 fallback or fixed-slot alias is authorized for UE6. This does not implement an AFW external-state provider. |
| Slate | A screenshot snapshot is inserted after HDR metadata. Decode the October or November SDR prefix only when exactly one validates; retain the full engine packet and all screenshot/HDR ownership. Ambiguous, invalid and unsupported HDR inputs preserve the original draw. |
| Render target | `FRenderTarget` moves to its own header. Its overload grouping and size/gamma accessors remain unchanged and are still instruction-validated before calls. Source viewport HDR bookkeeping changes are not fixed-offset resource contracts. |
| Renderer lifecycle | Renderer construction moves to the render thread and new frame/composite interfaces separate rendering from presentation. Native Fix is explicitly blocked before capture allocation or pair mutation until a matching UE6 binary verifies its private copy/destructor/ownership path. Ordinary Native is preserved. |
| RHI/RDG | MemStack moves to a new header but its reviewed Win64 prefix remains 0x28; command candidates still need module/executable validation. RDG early-async allocation ownership changes are not covered by old pooled-resource layouts. Removed WorkGraph virtuals/new viewport overloads invalidate guessed DynamicRHI slots; the existing UE6 fixed-slot creation refusal remains. |
| Reflection/objects | Default object destruction slots and garbage/unreachable bits remain as reviewed. FName atomic support does not change the default reflected-name representation. Struct/property discovery stays structural rather than adopting a guessed complete private layout. |
| Version boundaries | The reviewed numerical profile is 6.0.0, not arbitrary 6.0 patches. Later patches/minors fail closed. Same-version forks/snapshots still require their own runtime capability proofs and refreshed source manifest. |

UE4/UE5 game guards, rendering IDs, Mono/DIBR behavior and current health/
pacing/OpenXR worker fixes come from the shared baseline. They are not silently
reinterpreted as UE6-specific ABI proof.

## Verification and limitations

- Build and run the standalone SDK discovery tests, including Win64 ABI models
  and real D3D11/D3D12 WARP native-resource checks.
- Build the complete backend, Lua components and compatibility fixtures. New
  cases cover two-tag CVar storage, family offsets/name widths, both Slate
  layouts, ambiguous/truncated inputs, invalid/racing families and patch guards.
- Check all source-manifest hashes against both supplied archives. The checker
  supports explicitly absent baseline files for newly split headers, rejects
  unsafe/duplicate paths, and continues rejecting same-version critical drift.
- Check linked DLL/PDB identity and source paths for these exact worktrees and
  SDK commit. Keep the resulting build separate from `57workuevr`.

Tests model specific source contracts; they cannot establish a shipping game's
compiler settings, calling sequences, temporal ownership, tracking cadence or
pixels. Runtime/HMD verification remains **pending**. Native Fix's new private
renderer path is **not authorized** by this source pass. Source-reviewed
does not mean runtime-confirmed, including for Native, Synced, Ghost Fix,
Mono/DIBR, UI extraction or experimental OpenXR paths.

The supported source scope remains packaged Win64 (`WITH_EDITOR=0`) with the
reviewed conventional object/name configuration. Remote objects, non-default
state-stream, outlined four-byte reflected names, editor-only virtuals, runtime
feature-level-switch forks, arbitrary licensee layouts and HDR extraction are
not blanket-authorized.

## Repeatable 1-2 month refresh

1. Pin the new archive commit, whole-archive hash, Build.version and metadata.
2. Run `scripts/ue6/Compare-UE6Snapshot.ps1` against the current manifest first;
   do not regenerate hashes merely to make drift pass.
3. Compare the previous UE6 archive and current UE5 control. Follow moved
   declarations and transitive layout/virtual dependencies, not just old paths.
4. Merge the latest shared fixes in isolated UE6 worktrees; resolve semantic
   conflicts and preserve game/version/mode guards and frontend IDs.
5. Review each affected contract, update guarded adapters and negative fixtures,
   and only then replace the manifest target/baseline hashes.
6. Run standalone/full builds and tests, verify artifacts and record precisely
   what remains runtime-unverified. Push only the requested UE6Testing branches,
   SDK first, then UEVR with that exact submodule commit.

The snapshot checker accepts extracted source roots. Its manifest is not a
runtime allowlist and does not make an unreviewed 6.0.0 binary safe automatically.
